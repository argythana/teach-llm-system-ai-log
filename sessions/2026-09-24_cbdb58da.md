**Instructor:**

> explain to me what is cou offload?

**Claude:**

"CPU offload" is what happens when a model is too big for your GPU's memory but you
don't want to give up the GPU entirely: the model is split, and part of it runs on the
GPU and part on the CPU.

**How the split works:**

- A language model is a stack of **layers**; Qwen3-8B has 36. Each token is computed by
  passing through all of them, in order.
- If the whole model fits in VRAM, every layer runs on the GPU. That's llmfit's `GPU`
  path.
- If it doesn't fit, the engine puts as many layers as fit into VRAM and keeps the rest
  in ordinary RAM, where the CPU computes them. That's `CPU offload`.
- Every token has to go through the slow CPU layers too, so the speed lands between the
  two extremes. The more layers end up on the CPU, the closer it gets to CPU-only.

For Qwen3-8B at Q4_K_M, llmfit's three estimates were:

| Path        | Needs                               | Est. speed |
| ----------- | ----------------------------------- | ---------- |
| GPU         | 6.4 GB VRAM                         | 30.9 tok/s |
| CPU offload | at least 2 GB VRAM, the rest in RAM | 15.4 tok/s |
| CPU-only    | 6.4 GB RAM, no GPU                  | 2.9 tok/s  |

llmfit simply halves the GPU figure for offload. In reality it depends on how many
layers fit on the GPU.

**In Ollama:** you don't choose this, Ollama does it for you. When it loads a model, it
fills the free VRAM with layers and puts the rest in RAM. `ollama ps` then shows the
split, for example `30%/70% CPU/GPU` instead of `100% GPU`. That's the check guide 00c
now describes for the `gpu` tier. (In llama.cpp the same setting is exposed as `-ngl`,
the number of layers on the GPU; Ollama calls it `num_gpu`.)

**For the course:** offload matters to a student whose GPU has, say, 4–6 GB of VRAM.
qwen3:8b would run offloaded at roughly 15 tokens/s. That's usable, but qwen3:1.7b would
fit entirely on the same GPU and run at over 100. That's why guide 00c says a CPU/GPU
split means the `cpu` tier is the better choice. It's a speed-over-size trade-off, not a
hard rule.
